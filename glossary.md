# Глоссарий терминов — webserv

---

## Сеть и протоколы

### TCP (Transmission Control Protocol)
Надёжный потоковый протокол передачи данных. Гарантирует порядок доставки байт и отсутствие потерь. Важно: границ сообщений нет — `recv()` возвращает "сколько дали сейчас", а не "один запрос целиком". HTTP работает поверх TCP.

### IP / IPv4
Протокол адресации. IPv4-адреса вида `127.0.0.1`, `0.0.0.0`, `192.168.1.1`.
- `127.0.0.1` — loopback, только локальная машина.
- `0.0.0.0` — все сетевые интерфейсы (используется при `bind()`).

### HTTP (HyperText Transfer Protocol)
Текстовый протокол "запрос → ответ" поверх TCP. Структура запроса:
```
GET /path HTTP/1.1\r\n
Host: localhost\r\n
\r\n
[body]
```
Структура ответа:
```
HTTP/1.1 200 OK\r\n
Content-Length: 5\r\n
\r\n
Hello
```
Заголовки от тела отделяются `\r\n\r\n`.

### HTTP/1.0 vs HTTP/1.1
- **HTTP/1.0**: соединение закрывается после каждого запроса.
- **HTTP/1.1**: keep-alive по умолчанию, заголовок `Host` обязателен, поддержка chunked encoding.

### RFC (Request for Comments)
Официальные технические спецификации интернет-протоколов. Для webserv важны:
- **RFC 1945** — HTTP/1.0 (проще, хорошая отправная точка)
- **RFC 7230** — HTTP/1.1 синтаксис
- **RFC 7231** — HTTP/1.1 семантика (методы, статус коды)

## HTTP — методы и статус коды

### HTTP Methods
- **GET** — получить ресурс (файл, страницу).
- **POST** — отправить данные на сервер (upload, форма).
- **DELETE** — удалить ресурс.

### HTTP Status Codes
| Код | Смысл |
|-----|-------|
| 200 | OK |
| 201 | Created |
| 204 | No Content |
| 301 | Moved Permanently (редирект) |
| 302 | Found (временный редирект) |
| 400 | Bad Request |
| 403 | Forbidden |
| 404 | Not Found |
| 405 | Method Not Allowed |
| 413 | Payload Too Large |
| 431 | Request Header Fields Too Large |
| 500 | Internal Server Error |

### Content-Length
Заголовок сообщающий размер тела запроса/ответа в байтах. Сервер должен дождаться ровно этого числа байт — не больше, не меньше.

### Content-Type
Заголовок описывающий тип содержимого: `text/html`, `text/plain`, `application/json`, `image/jpeg` и т.д.

### Connection: close / keep-alive
- `Connection: close` — соединение закрывается после ответа.
- `Connection: keep-alive` — соединение остаётся открытым для следующих запросов.

## Сокеты и файловые дескрипторы

### Socket (сокет)
Объект в ядре ОС для сетевого взаимодействия. Создаётся через `socket()`, привязывается к адресу через `bind()`, переводится в режим прослушивания через `listen()`.

### fd (File Descriptor)
Целое число — идентификатор открытого ресурса (файл, сокет, pipe) в таблице дескрипторов процесса. `0` = stdin, `1` = stdout, `2` = stderr. Первый свободный — `3`.

### Listen-сокет (пассивный сокет)
Сокет который только принимает входящие соединения. Создаётся цепочкой: `socket()` → `bind()` → `listen()`. На нём никогда не делают `recv()`/`send()` — только `accept()`.

### Client-сокет (активный сокет)
Возвращается `accept()`. Это двусторонний канал с конкретным клиентом — на нём делают `recv()` и `send()`.

### Backlog
Параметр `listen()` — максимальный размер очереди входящих соединений которые ядро накапливает до вызова `accept()`. Типично 128.

### `accept()`
Извлекает одно соединение из очереди backlog и возвращает новый client fd. Вызывается в цикле пока не вернёт `-1` (очередь пуста).

### `recv()` / `send()`
Читают/пишут байты в/из сокета. Не гарантируют что прочитают/запишут всё за один вызов — partial read/write это норма.

### `bind()`
Привязывает сокет к конкретному адресу и порту.

### `SO_REUSEADDR`
Опция сокета (`setsockopt`). Позволяет переиспользовать порт сразу после перезапуска сервера, не дожидаясь окончания `TIME_WAIT` (~2 минуты).

### `TIME_WAIT`
Состояние TCP-соединения после закрытия. Ядро держит порт занятым ~2 минуты для защиты от старых пакетов. `SO_REUSEADDR` позволяет это обойти.

## Неблокирующий I/O

### Блокирующий vs неблокирующий режим
- **Блокирующий** (по умолчанию): `recv()`, `send()`, `accept()` приостанавливают процесс до завершения операции.
- **Неблокирующий** (`O_NONBLOCK`): если операция не может завершиться немедленно — возвращают `-1` с `errno = EAGAIN`.

### `O_NONBLOCK`
Флаг файлового дескриптора. Устанавливается через `fcntl(fd, F_SETFL, flags | O_NONBLOCK)`. Делает все I/O операции на fd немедленно возвращающимися.

### `fcntl()`
Системный вызов для управления параметрами fd. `F_GETFL` — получить текущие флаги, `F_SETFL` — установить новые.

### `EAGAIN` / `EWOULDBLOCK`
Значения `errno` при неблокирующей операции которая не может завершиться сейчас. Означает "попробуй позже" — это не ошибка, это норма.

## I/O мультиплексирование

### I/O Multiplexing (мультиплексирование)
Техника наблюдения за несколькими fd одновременно в одном потоке. Вместо блокировки на каждом fd по отдельности — ждём события на любом из них.

### `poll()`
Системный вызов. Принимает массив `struct pollfd`, засыпает, просыпается когда на каком-либо fd произошло событие. Возвращает количество fd с событиями.

```c
int poll(struct pollfd *fds, nfds_t nfds, int timeout);
```

### `struct pollfd`
```c
struct pollfd {
    int   fd;       // дескриптор
    short events;   // что ждём (заполняем мы)
    short revents;  // что случилось (заполняет ядро)
};
```

### `POLLIN` / `POLLOUT` / `POLLERR` / `POLLHUP`
Флаги-биты для `events`/`revents`:
- `POLLIN` — есть данные для чтения.
- `POLLOUT` — можно писать без блокировки.
- `POLLERR` — ошибка на fd.
- `POLLHUP` — соединение разорвано.

### `select()` / `epoll()` / `kqueue()`
Альтернативы `poll()`:
- `select()` — устаревший, ограничен 1024 fd.
- `epoll()` — Linux, масштабируется на тысячи соединений, O(1).
- `kqueue()` — macOS/BSD аналог epoll.

## Архитектура сервера

### Event Loop (событийный цикл)
Бесконечный цикл: `buildPollFds()` → `poll()` → обработка событий → повтор. Основа неблокирующего сервера.

### State Machine (стейт-машина)
Объект переходящий между состояниями в зависимости от событий. В webserv: `Connection` имеет состояния `READING` → `WRITING` → `CLOSING`. Текущее состояние определяет поведение.

### Incremental Parser (инкрементальный парсер)
Парсер который работает с неполными данными. Получил кусок — обработал сколько смог — вернул состояние — жди следующего куска. `HttpRequest::parse()` именно такой.

### Partial Send
`send()` может отправить меньше байт чем запрошено — это норма. Поэтому ответ хранится в буфере `out_` и дожимается по частям при следующих `POLLOUT`.

### Virtual Hosts
Несколько сайтов на одном IP/порту. Различаются по заголовку `Host:` в запросе. В webserv — несколько `server {}` блоков на одном порту.

## Конфигурация

### nginx-like конфиг
Текстовый файл состоящий из блоков `{ }` и директив заканчивающихся `;`. Комментарии `# ...`.

### Директива
Команда конфига: `name arg1 arg2 ... ;`

### Контекст
Уровень вложенности в конфиге: top-level, server-контекст, location-контекст.

### `server {}` блок
Описывает один виртуальный сервер: на каком порту слушать, какой root, error pages и т.д.

### `location {}` блок
Правила для конкретного URI-префикса: методы, root, autoindex, CGI и т.д.

### Longest Prefix Match
Алгоритм выбора `location`: из всех совпадающих по префиксу location-блоков побеждает тот у которого самый длинный префикс.

### EffectiveConfig / ResolvedConfig
Итоговые настройки для конкретного запроса — результат слияния server-уровня и location-уровня. Location перекрывает server там где задан.

## Файловая система

### URI (Uniform Resource Identifier)
Путь в HTTP-запросе: `/images/photo.jpg`. Это не путь на диске — это логический адрес ресурса.

### URL (Uniform Resource Locator)
URI + схема + хост: `http://localhost:8080/images/photo.jpg`. URL — это конкретный вид URI.

### Root
Директория на диске которая является корнем сайта. Путь к файлу = `root + URI`.

### Index
Файл по умолчанию для директории. Если запрошена директория и есть `index.html` — отдаётся он.

### Autoindex
Листинг содержимого директории в виде HTML-страницы. Включается директивой `autoindex on`. Если выключен и index-файла нет — 403.

### Redirect (return)
Перенаправление клиента на другой URL. Ответ с кодом 301/302 и заголовком `Location:`.

### Error Pages
Кастомные HTML-страницы для ошибок. Задаются в конфиге: `error_page 404 /errors/404.html`.

### Path Traversal
Атака через `../` в URI для выхода за пределы root: `/../../etc/passwd`. Защита: проверять URI на наличие `..` компонент.

### URL Decode (percent-encoding)
URI может содержать символы закодированные как `%XX` где XX — hex-код символа. Например пробел = `%20`. Сервер должен декодировать URI перед маппингом на файловую систему.

### MIME Type / Content-Type
Тип содержимого файла. Определяется по расширению: `.html` → `text/html`, `.jpg` → `image/jpeg`, `.js` → `application/javascript`.

### `stat()`
Системный вызов. Возвращает метаданные файла/директории: тип, размер, права, время модификации. Используется для проверки существования файла и определения его типа.

### `S_ISREG()` / `S_ISDIR()`
Макросы над `st_mode`: проверяют является ли файл обычным файлом или директорией.

### `opendir()` / `readdir()`
Функции для чтения содержимого директории. Используются при генерации autoindex.

## CGI (Common Gateway Interface)

### CGI
Протокол запуска внешних программ для генерации динамического контента. Сервер запускает скрипт (`.php`, `.py`), передаёт ему запрос через переменные окружения и stdin, читает ответ из stdout.

### CGI переменные окружения
`REQUEST_METHOD`, `QUERY_STRING`, `CONTENT_LENGTH`, `CONTENT_TYPE`, `PATH_INFO`, `SCRIPT_FILENAME` и другие — передаются CGI-скрипту.

### Chunked Transfer Encoding
Способ передавать body без `Content-Length` — кусками с указанием размера каждого куска. Для CGI: сервер должен "раз-чанковывать" запрос перед передачей скрипту, и обрабатывать chunked-ответ от скрипта.

## Безопасность и надёжность

### Keep-Alive
Переиспользование TCP-соединения для нескольких HTTP-запросов. Уменьшает задержки. Требует корректного парсинга границ запросов в буфере.

### Slowloris
Атака: клиент очень медленно присылает заголовки, удерживая соединение и ресурсы сервера. Защита: таймаут на чтение заголовков + лимит размера (`maxHeaderBytes` → 431).

### `client_max_body_size`
Лимит размера тела запроса. Если `Content-Length` превышает лимит → 413 Payload Too Large.

### Zombie Connection
Соединение которое числится открытым но уже не активно. Происходит если не удалять fd из `connections_` при закрытии.

## Инструменты отладки

### `curl`
Утилита для HTTP-запросов из командной строки. `-v` показывает полный диалог заголовков.

### `telnet`
Позволяет вручную отправлять сырые HTTP-запросы и видеть сырые ответы байт в байт.

### `netcat` (`nc`)
Аналог telnet, удобен для скриптования тестов.

### `strace`
Трассировка системных вызовов процесса. Полезно для отладки зависаний и неожиданного поведения.

### `valgrind`
Детектор утечек памяти и ошибок работы с памятью.

### ASAN / UBSAN
Компиляторные санитайзеры. ASAN — утечки и out-of-bounds. UBSAN — undefined behavior. Включаются флагами `-fsanitize=address,undefined`.

¿Qué es relink en realidad?

Relink es cuando se vuelve a ejecutar el comando de linking:

$(CXX) $(OBJS) -o $(NAME)

Es decir:

  • los archivos objeto ya existen,
  • pero el binario final se genera de nuevo.

¿Cuándo hace make un relink?

make solo mira los timestamps. Esta es la regla:

$(NAME): $(OBJS)
	$(CXX) $(OBJS) -o $(NAME)
Si cualquier $(OBJ) es más nuevo que $(NAME) → hay que relinkear.

Eso es todo. Sin magia.

¿Qué es un “relink innecesario”?

make
make
make

…y el linking se produce cada vez, aunque el código, los objetos y el binario estén actualizados. Esto es un bad Makefile.

La gran confusión de los alumnos del campus 😏

Hacen esto:

$(NAME): $(OBJS) Makefile includes.hpp
“Ahora el relink está arreglado”

NO, JODER.

Han añadido nuevas dependencias y aumentado la cantidad de situaciones en las que se ejecuta el linking. Han hecho casi lo contrario.

¿Qué hace realmente una dependencia de un header?

main.o: main.cpp includes.hpp
si includes.hpp ha cambiado → hay que recompilar main.o

Esto es una compile dependency.

NO es relink.

¿Por qué entonces ocurre relink después?

  1. se recompiló main.o
  2. su timestamp es ahora más nuevo
  3. $(NAME) es más antiguo que el objeto
  4. make ejecuta el linking
el relink es una CONSECUENCIA de la recompilación del objeto, no una dependencia directa del header.

El punto más importante

Un header no debe ser nunca una dependencia directa del binario.

$(NAME): $(OBJS) includes.hpp  ← esto suele ser incorrecto

El linker no lee headers — son para el compilador, no para el linker.

Modelo correcto

main.o: main.cpp includes.hpp
$(NAME): $(OBJS)

¿Por qué algunos añaden Makefile como dependencia?

$(OBJS): Makefile
“si cambian los flags de compilación → recompila todo”

Pero esto es compile invalidation, NO relink avoidance.

make es bastante tonto

make no entiende include graph, compile flags, ABI ni cambios semánticos. Solo sabe: target, prerequisites, timestamps.

Makefile minimal correcto

NAME = app
SRCS = main.cpp test.cpp
OBJS = $(SRCS:.cpp=.o)
CXX  = c++
CXXFLAGS = -Wall -Wextra -Werror

$(NAME): $(OBJS)
	$(CXX) $(CXXFLAGS) $(OBJS) -o $(NAME)

%.o: %.cpp
	$(CXX) $(CXXFLAGS) -c $< -o $@

clean:
	rm -f $(OBJS)

fclean: clean
	rm -f $(NAME)

re: fclean all
all: $(NAME)
.PHONY: all clean fclean re

Versión production (recomendada)

CXXFLAGS += -MMD -MP
DEPS = $(OBJS:.o=.d)
-include $(DEPS)

Así los headers se rastrean automáticamente. Nivel adulto 😏

$(NAME): $(OBJS)

I aquestes són tres coses COMPLETAMENT DIFERENTS, collons.

Anem a desglossar-ho amb cura, perquè aquí és important entendre la mecànica real de make, i no repetir encanteris com un xamà amb un tambor. 😏

Què és relink en realitat?

$(CXX) $(OBJS) -o $(NAME)
  • els fitxers objecte ja existeixen,
  • però el binari final es genera de nou.

Quan fa make un relink?

$(NAME): $(OBJS)
	$(CXX) $(OBJS) -o $(NAME)
Si qualsevol $(OBJ) és més nou que $(NAME) → cal relinkejar.

Això és tot. Sense màgia.

Què és un “relink innecessari”?

make
make
make

…i el linking es produeix cada vegada, tot i que res ha canviat. Això és un bad Makefile.

La gran confusió dels alumnes del campus 😏

$(NAME): $(OBJS) Makefile includes.hpp
“Ara el relink està arreglat”

NO, COLLONS.

Han afegit noves dependències i augmentat el nombre de situacions en les quals s’executa el linking. Han fet gairebé el contrari.

Què fa realment una dependència d’un header?

main.o: main.cpp includes.hpp
si includes.hpp ha canviat → cal recompilar main.o

Això és una compile dependency.

NO és relink.

Per què aleshores ocorre relink?

  1. es va recompilar main.o
  2. el seu timestamp és ara més nou
  3. $(NAME) és més antic que l’objecte
  4. make executa el linking
el relink és una CONSEQÜÈNCIA de la recompilació de l’objecte, no una dependència directa del header.

El punt més important

$(NAME): $(OBJS) includes.hpp  ← això sol ser incorrecte

El linker no llegeix headers — els headers són per al compilador, no per al linker.

Model correcte

main.o: main.cpp includes.hpp
$(NAME): $(OBJS)

Per què alguns afegeixen Makefile com a dependència?

$(OBJS): Makefile
“si canvien els flags de compilació → recompila-ho tot”

Però això és compile invalidation, NO relink avoidance.

make és bastant ximple

make no entén include graphs, compile flags, ABI ni canvis semàntics. Només sap: target, prerequisites, timestamps.

Makefile minimal correcte

NAME = app
SRCS = main.cpp test.cpp
OBJS = $(SRCS:.cpp=.o)
CXX  = c++
CXXFLAGS = -Wall -Wextra -Werror

$(NAME): $(OBJS)
	$(CXX) $(CXXFLAGS) $(OBJS) -o $(NAME)

%.o: %.cpp
	$(CXX) $(CXXFLAGS) -c $< -o $@

clean:
	rm -f $(OBJS)

fclean: clean
	rm -f $(NAME)

re: fclean all
all: $(NAME)
.PHONY: all clean fclean re

Versió production (recomanada)

CXXFLAGS += -MMD -MP
DEPS = $(OBJS:.o=.d)
-include $(DEPS)

Així els headers es rastregen automàticament. Nivell adult 😏
